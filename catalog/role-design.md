# 1688 运营职责与能力设计

当前组织为三个核心角色，任务路由的唯一来源是 [task-routing.json](task-routing.json)。其中 `routes[]` 每项以 `id/owner/delegation_policy/capability/skill/rules` 表示任务去向及委派方式；[agent-registry.json](agent-registry.json) 的 `agents` 定义核心角色，`skills` 定义按需能力，`legacy_aliases` 定义旧名称到新组织的映射。本文件解释设计，不另建一套路由表。

经营主流程按[销售增长运营流程](../references/sales-growth-workflow.md)：总控完成完整周/月销售诊断，商品与流量按结论或公司重点要求逐链接处理；人工步骤交付执行方案，措施生效后观察并到期评估，重点产品持续跟踪、投流每日检查。月度复盘复用现有总控和经营分析能力，不增加核心角色。

## 核心职责与实际执行

| 核心角色 | 责任 | 执行方式 |
|---|---|---|
| `operations_director` | 经营目标、策略版本、优先级、经营摘要、跨任务协调、措施观察和结果验收 | 根项目主 Agent 直接承担，不再启动总控子 Agent |
| `product_operations` | 商品诊断、标题/属性方案、图片、新品准备、竞争和市场研究；在授权及能力范围内执行商品动作 | 总控有子代理工具时实际委派；已有领域会话直接执行，不重复启动自身 |
| `traffic_operations` | 自然、搜索、推荐、广告渠道分析、行业比较和投放策略 | 总控有子代理工具时实际委派；现有查询与未核实广告写入能力分别标记 |

明确的小任务直接交对应领域，不触发全店分析。复核 `operations_review` 是按需临时任务；询盘转化每日轻量监测由总控完成，符合异常、新事实或复查条件后，按 `conversion_analysis` 路由实际委派临时分析专项。其他客户运营、ERP、采购等按需加载或委派，不恢复31个常驻岗位。总控、领域直接会话、旧名映射和无工具代行的行为详见[委派约定](../references/delegation.md)。读取技能、角色元数据或目录归属不能冒充真实启动记录。

角色不是工具权限沙箱；模型连接和工具能力可能由宿主继承。规划负责人不意味着工具只能由它读取；共享查询允许复用，需要唯一的是具体业务任务负责人和同一动作的执行路径。写入按[执行协议](../references/execution-protocol.md)处理，不能因工具位于某角色目录而扩大授权。

## 能力组织与保留规则

商品、流量领域通过短技能入口加载所需规则，经营分析分别保留单日T+1、长周期、成本利润口径。竞争比较与市场机会、新商品草稿与正式发布、图片生成与商品应用、CRM筛选与触达、人工询盘与AI接待、买家采购与卖家经营分别保持业务边界。

客户转化保留画像分层、询盘、AI接待、报价和触达子流程；每日分析仅使用[询盘与转化分析模块](../.agents/skills/1688-customer-conversion/references/conversion-analysis.md)的明确查询范围，输出问题、责任建议及观察条件，不自动跟进客户或修改接待配置。显式客户运营任务仍按原子流程和授权执行。ERP共享入口保留聚水潭、吉客云各自授权、订阅、字段和粒度适配。客户、库存、履约信号仍可进入经营摘要或触发专项调查。采购研究、买家事务和分销按任务使用；暂不默认参与每日运营不等于删除能力。

连接、平台规则检索和组件维护是共享能力。平台知识检索与店铺数据RAG不能混用。内部卡片、泛化网关及身份审计接口不作为每日独立经营任务，但来源业务流程要求的依赖和前置条件必须保留并核验，不能自行删掉。

已有 [image-agent](../agents/image-agent/AGENTS.md) 及图片规则、设计模板保持原样，商品运营按图片任务加载。旧 `creative_studio` 映射到图片能力，业务规则继续保留，不再设置重复岗位。图片自身入口的执行和不主动再启动子代理规则继续有效。

原31份技能文本逐份保存在 `references/business-rules/<原技能名>/RULES.md`。旧名称的业务交接通过 `legacy_aliases` 解析为新负责人和能力；规则原文的职责名称不是重新启用旧岗位的命令。业务步骤、数值、前置条件、范围、必要交互、提示和免责声明不因组织合并删改。相同语义的规则通过引用复用，有差异的条款保留并列；宿主适配和适用性疑问记录原文、来源和待核验项，未经用户明确同意不改变业务规则。

标题来源规则的热词/年份词曝光预估数值和免责声明继续保留，不能因没有本店实测而排除；展示时区分预估与实际观测。图搜等来源差异先核验，不用本次路由重构静默裁决。历史方案和业务报告用于追溯，不作为新的执行入口。

## 工具快照分类及使用边界

原目录来自用户指定的 `/Users/shileqi/Documents/ChatGPT/jacky/outputs/1688-capabilities/2026-10-25-tool-catalog.md`，快照日期为2026-10-25（Asia/Shanghai），包含205个工具。原始平台说明保存在[原目录](2026-10-25-tool-catalog.md)及[工具路由](tool-routing.json)，参数快照见[live-tool-schemas.json](live-tool-schemas.json)。这些是历史能力证据，不保证当前连接、权限、参数或业务动作已逐项实测。

原设计按工具默认归属定义角色，后续又增加单项工作流角色，造成职责与路由重复。旧 `primary_agent`/`planning_hint` 等归属仅是来源或规划线索；本轮任务负责人从 `task-routing.json` 取得，当前工具能力仍以实时发现和 `describe_tool` 为准。不能据元数据还原云端源码、内部提示词或未接通接口。

以下分类保留原目录含义，不作为执行白名单：

- 操作类别为 `query`（查询）、`write`（写入/外部动作）、`generate`（生成/处理）、`authentication`（认证/连接）与 `unclassified`（未分类），可以多类并存。
- 买卖方标签为 `seller`、`buyer`、`shared`、`unknown`；`surface=internal_component` 表示内部组件。短描述不足以确定身份时保留 `unknown`，不得从名称猜买卖方权限。
- `reviewed_query` 是桥接器审核的查询标记；`unclassified/potential_changes` 既不是只读保证，也不证明一定会写数据。按真实动作和Schema核实。
- 使用业务工具时先核对网关、当前店铺与连接状态，再取得实际工具的 `describe_tool`。实时参数、权限、副作用、确认、成本与幂等要求不能被角色文档覆盖，也不能猜造参数。
- 制作Agent包、查询、生成方案与发消息、修改商品、开票、物流下单是不同动作，按用户具体任务和原有业务前置执行；不能从前者推定后者授权。
- 含Token、Cookie、AK、临时上传凭证或商家凭证的结果不可进入持久报告；角色路由不需要这些值。

## 容易误判的工具

- `quotation_skill_load` 名为加载，但没有方案时会自动建草稿；查看已有生效方案应使用 `quotation_skill_get_detail`。
- `newton_ai_crm_plan_operation` 同时支持查询、创建和状态修改；需依据实时参数辨认动作，创建/修改受主账号权限约束。
- `create_cow_boy` 需要先模拟并确认，且非幂等；不能把超时当成失败并重复创建。知识答案、启停和接待等级更新均有源说明中的确认要求。
- `tool_cpv_spi_execute` 和 `tool_one_click_spi_execute` 各有明确的 before_check 前置工具；一键执行还可能发布会员号动态。
- `order_view` 是价格和下单预览；商品草稿、发品链接与正式发布也不能互相替代。
- `cha88_company_report_submit` 是异步任务提交，随后查询报告；图片和预测工具也应区分提交、运行和完成状态。
- 吉客云查询先确认授权；聚水潭各接口需检查实时授权/路由前提。原目录中的官方拼写 `selelctFields` 保留在原文中，不自行改名。
- `newton_webim_im_chat_gateway_invoke` 是泛化网关；卡片和组件的短描述不能证明其无写入副作用。
- `1688_procurement_digital_human_tool` 的原采购询盘技能明确说明它会创建对外询盘；路由已引用该额外证据标记为写入，不将找货授权扩为询盘发布。

## 持续运营和可验证范围

[运营周期约定](../references/operating-cycle.md)区分滚动监测基线、行动前固定基线、阶段起点与经营目标。每日先查已有措施，指标仍差但观察尚未成熟时不重复修改；每周更新策略不清零原措施。[询盘转化本地状态模块](../references/conversion-state.md)负责该层问题记录、分析请求去重及委派回执，并对其自身文件事务加锁；不负责远端工具执行或全项目并发控制。每日与周度独立定时任务按用户要求暂不创建。

执行能力分开记录：已有可靠查询、已有验证写入、待核实或未接通。商品基础属性与SKU/销售信息当前边界、图片默认后端和实际页面核查要求继续遵循根规则及[runtime](../references/runtime.md)。没有验证广告写接口时不承诺创建计划或调预算；保留跨平台源码不等于接通大泽、店小宝或DSers。

校验关注每个活跃任务的唯一负责人、能力和完整规则引用、31个旧名称的去向、角色入口一致性及工具原说明保留；不以每个工具各制造一个岗位为目标。离线路由校验和文本完整性核对不等于业务接口实测。
