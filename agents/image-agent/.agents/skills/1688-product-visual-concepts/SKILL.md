# 产品视觉概念

从本机 `ai-product-designer` 迁移概念设计方法。只在用户要求研发或新产品方案时使用，不把普通商品图请求升级为产品开发项目。

## 方法

1. 复用用户已给出的用途、人群、类目、尺寸、成本目标、工艺/材料限制和视觉偏好，只问影响正确性的缺口。
2. 只有市场证据能改变方案时，使用当前可用的检索能力进行适量研究，尊重“不联网/不调研”的要求。引用真实来源，无法检索时不冒充做过市场验证。
3. 按用户数量提出可区分的方案；未指定时按复杂度选少量方案，不强制固定三款。每项解释定位、解决的问题、外观/结构差异、材料/工艺建议及主要制造不确定性。
4. 区分已确认参数、设计目标与待验证假设。成本、MOQ、认证、交期、承重等没有来源时不能写成供应商承诺。
5. 用户要求视觉图时，经 [图片设计技能](../1688-image-design/SKILL.md) 与 [执行适配](../1688-image-design/references/generation-runtime.md) 生成真实产物。比较方案应保持可比较的角度与展示条件，但风格服从任务。只要文字方案时不调用生图。
6. 按用户重视的因素比较并给出有条件的建议，不把概念图说成可直接量产、现货SKU或已选供应商。

## 交付与后续

每个方案保留主题、用途/价值、关键设计决策、真实状态与待验证事项。用户要求成图时关联实际图片，不虚构图片URL。方案数量和参数表长度由内容决定，不补空泛字段凑数。

已选方案的细化保留身份与接受的设计。寻找工厂、发询盘、上架商品属于另外的请求，不自动执行；用户已要求相关后续时交给当前可用业务工具并沿用授权。不要依赖原Accio供应商技能或界面输出标签。
