# 共用变更执行协议

本协议适用于当前技能授权范围内的业务修改、创建、发送及其他外部动作。它是新增的文档流程，尚未实现统一写入代理、数据库事务、程序锁或网关硬拦截；工具能力和权限仍由当前宿主及实时接口决定。执行者必须主动遵循，不能因文档存在而声称系统已经技术性阻止违规写入。

本协议不增加通用二次批准开关，也不取消原有业务步骤、必要交互或工具前置。遵循[共用执行约定](runtime.md)、当前技能及完整适用规则；用户已明确的授权继续有效，缺少真实信息或必要决定时先完成不依赖它的工作。

## 结构化变更单

修改前在任务指定记录位置或本轮 `reports/` 中保存变更单，执行与恢复沿用稳定 `action_id`。同一经营问题跨天延续原 `issue_id`；同一次动作的重查、恢复不再生成一个看似全新的措施。

销售增长任务按[逐链接执行与人工交接](sales-growth-workflow.md#逐链接执行与人工交接)关联本次周/月结论或公司重点依据。执行方案逐链接记录；不支持的接口和人工环节保存完整步骤、现值/目标值、素材、负责人/待认领及完成证据要求。待人工执行与已生效分开，只有真实执行确认后才设置观察起点。投流同样先准备具体计划、再按条件执行；有限观察与公司长期重点身份按[两类观察](sales-growth-workflow.md#两类观察)分别维护。

| 字段组 | 内容 |
|---|---|
| 标识与责任 | `action_id`、`issue_id`、`run_id`、任务负责人、具体执行者及真实子代理ID（如有）、策略版本、能力/技能/规则路径 |
| 对象和范围 | 真实店铺引用、买卖身份、商品/计划/客户/订单等对象、字段/动作、目标数量或受众范围 |
| 依据 | 问题证据、假设或事实纠错理由、相关既有措施和观察状态、依赖动作 |
| 授权 | 用户明确任务或已有效授权的依据、允许动作及幅度、预算/数量/渠道/内容限制、尚缺的必要决定 |
| 差异 | 当前真实值/状态、目标值/状态、修改前证据；不适用字段明确标记原因，不猜值 |
| 能力与前置 | 实时工具名和Schema依据、可调用性、业务前置结果、参数来源、已知副作用与恢复能力 |
| 效果观察 | 固定基线引用、主要/保护指标、评估条件、最晚重新审视时间及提前干预条件；纯事实纠错注明适用的正确性验收 |
| 执行与核验 | 提交时间、工具回执、任务或业务ID、当前结果、后台回读、非目标字段差异、失败/未知原因 |
| 后续 | 展示核查状态、观察/复盘状态、下一步及责任人、恢复或取消记录、证据路径 |

金额、单位、SKU和参数均来自当前已核实事实与工具定义。日志不得包含Token、Cookie、AK、Secret或其他凭证。原始证据按来源保存，不把模型整理后的文本冒充工具回执。

## 执行前检查

1. **读取已有行动。** 按[运营周期约定](operating-cycle.md)检查同对象、同问题、相关字段是否已有待执行、结果未知或观察中措施。相同依据不重复启动；存在新依据时记录与旧措施的关系。
2. **核对数据和策略。** 确认数据区间、实际截止时间、口径及缺失值；写入前核对策略版本，过时方案重新评估。
3. **核对授权及业务事实。** 不将分析授权扩为修改或触达，不将方案授权扩为发送；既有明确授权不重复索取。内容、对象或副作用超出范围时仅补齐尚缺决定。
4. **核对当前对象。** 从实时工具确认归属、当前值和状态，与变更单中的修改前证据比较。发现人工或其他系统已经改动时保存差异并重新评估，不直接覆盖。
5. **核对真实能力。** 按runtime检查网关、店铺、工具最新说明与Schema。旧文档、源码和路由中有名称不代表接口当前可执行；未接通步骤明确保留为未完成。
6. **完成原业务前置。** 商品变更 `before_check` 成功后才能对应 `execute`；AI接待模拟确认、知识入库确认、报价公式确认等依原流程和实时定义执行，不能被通用变更单替代。
7. **安排唯一执行者。** 同一对象的写入串行，相关商品与投流动作先协调；没有程序锁时以明确交接和记录避免双执行，不宣称具备硬隔离。

原规则要求的参数、步骤、适用条件及免责声明完整保留。有来源条款或宿主差异待核验时记录原文与来源，并继续完成不受影响的部分；未经用户明确同意不自行删改或停用规则。

广告决策中用户已授权裁决的冲突按[广告经营决策修正规则](ad-decision-policy.md)执行。减投、暂停等可以作为有依据的方案选项；实际操作仍检查既有授权、当前合同条件、实时接口和回读能力，不据此假设已具备广告执行接口。

## 提交、未知结果与回读

使用能完成本次动作的明确接口，按真实参数提交，不以通用网关或猜测服务名绕过缺失能力。每次动作保存实际回执和返回标识。异步任务继续查询同一任务，不能因处理中、超时或暂未出现在列表而重复创建。

回包成功先按业务定义解释：请求受理、任务运行、保存草稿、正式生效、送达、订单创建和支付都是不同状态。对可回读字段核对实际值；需要进一步状态查询时完成后才作最终判断。记录意外的非目标字段变化，不在未经检查时声称其他字段完全未变。

网络超时、执行中断或结果不明时标记 `结果未知`，先回读对象、查询原任务或检查既有回执，再决定恢复。未知结果不能自动当失败重试；不造成重复发送、创建、订单、投诉、物流预约或开票。接口不支持回读且无法确认时如实保留未知，不能编造幂等保障。

任务接管时先停止或确认原执行者状态，再更新执行责任。仅当确定先前未执行且业务允许重试，或接口具有已核实的幂等机制时才继续提交。没有真实接口支持时，`action_id` 只是本地跟踪编号，不是服务端幂等键。

## 恢复与外部改动

保留修改前值不代表任何操作都可自动撤销。需要恢复时，核对当前值是否仍是本措施产生的结果、是否已被人工或其他系统更新、恢复接口是否可用，以及当前授权和业务前置。存在更新的有效修改时不得盲目写回旧值。

无法恢复的动作如实说明；已发送消息、发券、付费或订单状态变化不能用“恢复旧字段”抵消。恢复是新的关联执行步骤，保存原因、具体差异、回执与回读，并处理对原观察的影响。

## 专项边界与验收

- 标题、基础属性、主图与销售信息分开。当前SKU/阶梯价等销售信息仍按runtime规定需要后台手动编辑，不用通用属性或一键接口试写。
- 图片方案、实际生成、上传图片银行、应用到商品分别确认范围；默认采用现有image-agent和当前imagegen，沿用明确指定服务，不自动切换。
- 后台回读只证明后台字段。实际展示效果优先由用户人工核查；使用网页、浏览器或其他展示核查工具前须依根规则说明对象、工具、内容及可能操作，并取得明确同意。委派不改变这一要求。
- 客户圈选、计划编辑、旺旺/优惠券/通知发送分别确认动作范围；采购、退款和发票先确认买卖身份。模型/工具权限继承不扩大用户授权。
- 流量与投放分析能力不证明广告写入能力。当前尚未核实的计划创建、预算或参数写入，只能标为待验证能力和未执行项。
- 原规则的预估（包括标题曝光数值规则）与实测分列；来源条件和免责声明继续保留，不能把计算预估当真实执行成效。

完成验收至少说明：执行了什么、后台核验结果、实际页面核查状态、未完成或未知部分、后续观察条件、证据位置及真实执行角色。总控统一协调验收；领域直接会话可在其授权内完成并保存相同记录，不必为形式再启动总控。
