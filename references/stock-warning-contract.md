# 库存预警字段与校验

仅适用 `1688_query_shop_data` 的 `ITEM /item/skuStockWarning` 结果。商品诊断负责生成校验结果，运营总控负责检查后再汇总；其他角色读到该接口也使用此规则。工具归属表不表示实际调用了另一个 Agent。

## 口径

接口说明（2026-10-26取得）明确：“可用库存(离线)”和“建议库存”来自 T+1 离线快照；接口不自动过滤实时已充足的旧预警。原始“预警等级”“库存缺口”和“预警总数”描述离线候选，不能直接用作当前风险。

先按共用执行约定发现、查询接口，再把原始 JSON 保存到本次任务的证据目录。运行 [normalize_stock_warning.py](../scripts/normalize_stock_warning.py)；它只读本地回执并生成派生结果，不调用网关或修改库存。在工作区根目录执行：

```sh
python3 scripts/normalize_stock_warning.py <原始回执.json> --output <库存校验.json>
```

输出文件不能覆盖输入或已有文件。兼容含 result/content/structuredContent 的工具回执及已解包的 data；解析失败、工具失败、已知接口错误码或无明确结果结构时退出且不生成成功文件。NO_DATA 单独退出（状态码3），与成功的空列表分别报告，不能据此声称全店无库存风险。同一商品/SKU重复返回时拒绝生成，先核对重复或冲突证据，避免重复计数或同时报充足与缺货。

## 对外和交接字段

|原始字段|派生字段|使用要求|
|---|---|---|
|预警等级|离线预警等级|只作历史候选说明，不直接写“当前已断货”|
|可用库存(离线)|离线可用库存|不得与实时库存等同|
|建议库存|离线建议库存|只是该接口的参考阈值，不等于已批准采购数量|
|库存缺口|离线库存缺口|不得作为当前补货量|
|实时可售库存、实时库存口径|原名保留|区分SKU级、商品级；缺失不是0|
|无|当前预警状态、当前库存缺口、列入当前库存风险、校验说明|由脚本计算，汇总只能采用这些当前字段|
|预警总数|离线预警总数|不能当成当前有效预警数|
|无|本页当前有效预警数、本页待核验记录数、本页已解除预警数|仅覆盖本次返回记录；不能扩为全店结果|

原始回执不改写；派生结果保留证据文件、查询时间（未返回则为空，不拿处理时间冒充）、店铺归属与分页。交接时附两份文件。实时状态只代表取数时的页面可售口径，不证明仓储实存或任何库存变化发生时间。

## 判断顺序

1. 工具失败不产生当前库存结论；NO_DATA 单独标注无返回候选。即使 success=true，仍要检查商品/SKU身份、实时数值和库存口径是否完整。
2. 仅在商品ID、SKU ID均明确且实时口径是“该SKU的可售库存”时自动比较。商品级回退可能来自单规格或SKU已删除，不自动套给旧SKU；应补查 baseInfo 核身份，未核清前标“待核验”，也不能计入已确认缺货。
3. 实时可售=0：状态“当前可售为0”；建议库存缺失时当前缺口仍为空，不猜补货量。
4. 实时可售>0且达到建议库存：状态“已达建议库存”，当前缺口0，不列入当前库存风险。不写“已补货”，因为没有补货事件证据。
5. 0<实时可售<建议库存：状态“低于建议库存”，当前缺口=建议库存−实时可售。
6. 实时库存缺失、null、空串、布尔值、非数值、非有限数或负值均不是0；建议库存无效时也不能判断是否达到阈值。状态“待核验”，保留缺口而不自动报断货。

已达阈值的旧预警从当前问题和补货清单移除；同一SKU的历史与实时数值不同，本身不能作为“库存异常”或销售下降原因。字段或口径不完整时，说明具体缺口，避免笼统写“库存冲突”。
