# 1688 业务执行参考

本文件按[加载清单](context-loading.md)读取相关章节，不是所有会话的启动必读。角色及最小边界见根[AGENTS.md](../AGENTS.md)，业务流程见[销售增长流程](sales-growth-workflow.md)；不在各入口重复全文。

## 角色、路由与规则加载

[任务路由](../catalog/task-routing.json)决定负责人、阶段和适用模块。业务执行者读取选中的完整规则及其必要来源，总控协调不预先加载领域细则。旧名称按[注册表](../catalog/agent-registry.json)映射；`source/`内私有宿主命令不因文件存在而可用。来源原文保留，数值规则、条件与免责声明继续有效；预估与实际观测分开，有差异按[规则登记](rule-questions.md)处理。广告限定条款优先应用[已授权修正](ad-decision-policy.md)，不扩大操作权限。本店目标按[有效策略](account-strategies/songtai-sales-growth.md)，首次业务运行、版本变化或歧义时核对原文。

## 连接和工具

1. 首次需要使用 Accio 1688 业务工具或账号切换后调用 `mcp__accio_1688__bridge_status({check_gateway:true})`，确认当前网关和授权店铺。使用这些工具时保持 Accio 运行。仅做本地分析或根据用户提供素材调用默认图片后端时，无需连接网关。
2. 先使用阶段加载结果的 `tool_context` 候选，按需读取[当前工具定义](../catalog/current-tool-definitions.json)和[任务分工](../catalog/tool-assignments.json)中相关项。定义带采集时间，分工只帮助定位；缺项或能力变化时再用 `search_tools` 作针对性发现。执行前使用 `describe_tool({tool_name:...})` 获取最新业务说明和完整 Schema，再调用 `call_tool({tool_name:...,arguments:{...},store_ref:...})`。工具宿主命名可能不同，使用实际加载的 MCP 工具。
3. `catalog/tool-routing.json`、`catalog/live-tool-schemas.json` 的旧快照保留作迁移参考，不是当前能力上限。`scripts/tool_catalog.py` 只作本地元数据导入、比对和候选查询，不接通网关、不执行业务；新增或变化的工具仍需核实实时定义与本轮范围。`planning_hint` 仅辅助分工；`reviewed_query` 是桥接器已审核的查询标记，`unclassified/potential_changes` 不能被当成只读承诺，也不能被误称一定会写数据。结合实际动作、Schema 和用户任务判断。
4. 店铺由网关注入；多店选择只能用网关提供的 `store_ref`，不能编造值，不能用目录中的账号号锁定身份。若网关未提供可选店铺引用，不假装已完成多店查询。禁止覆盖 `NEWTON_SHOP_LOGIN_ID`、`accio_id`、`connect_id` 等内部路由/认证字段。正常业务对象 ID 依 Schema 传递。
5. 自由取数先 `1688_rag_query_api_info` 获得有依据的 `dataSource/apiPath/params`，再 `1688_query_shop_data`；本地旧 API 文档只帮助解释，不代替实时接口发现。日期、设备、分页枚举按具体接口定义，不能把一个接口的统一映射套到所有接口；实时说明与旧来源冲突时保留差异，有限验证有文档依据的参数，不凭空试参或预先断言失败原因。平台规则检索使用 `tool_1688_knowledge_rag_query`，两种 RAG 不互相替代。

本轮查询在原证据目录逐工具、具体接口及范围记录：要回答的决定、请求字段和有依据的参数、对象和区间、尝试时间、状态、回执引用、实际返回字段、分页/覆盖与关联缺口、下一条有价值的来源。状态分别为 `not_attempted`（未尝试）、`succeeded`（取得所述范围数据）、`empty`（未返回业务数据）、`failed`（调用失败）、`unsupported`（有实时定义或明确返回证明该项不支持）、`requires_user_action`（需登录、权限处理等具体用户操作）。外层 `success:true` 不能覆盖内层错误、空结果或截断；部分成功注明成功与缺失范围。一次空表或失败不能升级为整体不可取得，未尝试不能写成已穷尽；旧成功不证明当前权限、全量覆盖或商品/计划/素材关联。

权限拒绝先保存原始错误和被拒对象、时间及操作范围，用实时说明和已有权限信息核实是批量方式、特定对象还是整个数据访问受限。范围未明确时暂停受影响的数据查询，继续在已有范围内核对工具定义及权限说明；确需用户或平台处理才交具体阻塞，不把澄清工作直接推给用户。不通过换工具、拆批或换身份自动绕过；已确认仍允许的独立查询范围按原用户授权继续，不重复索取执行许可。接口空结果、能力未知和权限拒绝分别处理，不能混写成“平台没有接口”。

按[决策与阶段交付](sales-growth-workflow.md#决策与阶段交付)选择查询路径：先确认决定需要的对象与字段，复用当前候选和同范围成功回执；存在影响决定的缺口时，再有限发现相关工具或接口，按价值核对官方接口、可导出报表及已有授权范围的后台页面，避免无目的遍历。不同路径的店铺、日期、覆盖及关联键均须核对；已有授权可继续，新增网页展示核查沿用根入口要求。重复查询须有参数依据、范围变化或新证据；停止时说明重要未尝试来源为何不会改变当前决定、不可行或超出本轮范围，不宣称永久没有能力。

## 默认图片方案

所有角色的主图、副图、详情图、场景图、模特图、工厂展示图及图片编辑任务，默认由 `product_operations` 加载图片能力，并采用已有 [image-agent](../agents/image-agent/AGENTS.md)。旧 `creative_studio` 通过注册表映射到该能力，保留其完整规则而不另设岗位。Codex 负责商品理解、方案、提示词和验收，实际生成遵循其 [generation-runtime.md](../agents/image-agent/.agents/skills/1688-image-design/references/generation-runtime.md)，默认使用当前会话的 `imagegen` 内置路径。用户明确只要方案/提示词时不提交生成任务；本店正常优化中的成品制作范围按[成品审核与应用](sales-growth-workflow.md#成品审核与应用)承接，不另等一次“开始生图”确认。

用户已明确选择的服务和模型继续有效。Accio 云端图片生成、编辑、诊断工具与自定义 CLI/API 路径仅在用户明确选择时使用；默认路径缺失或失败时交付已完成材料、精确缺项及承接方式，图片制作仍标未完成，不自动切换后端。工具目录中的图片工具保留可选能力归属，不表示默认使用它们。用户已要求应用素材，或按本店常设范围批准具体成品版本后，可继续完成应用所需的图片银行上传、资源转换和商品修改，不重复索取这些必要步骤的批准；图片存储、商品数据查询与生图后端分别选择，上传后的真实资源须对应获批版本。

## 执行边界

按用户具体请求及有效常设范围执行已获授权的动作，不添加统一解锁开关，不重复索取已明确给出的授权。本店经营优化中的标题、主图、详情按[成品审核与应用](sales-growth-workflow.md#成品审核与应用)先制成品，用户批准具体版本后应用；纯取数、明确仅查证/仅方案/不生成/不应用及本地规则维护不进入该业务链。该范围不扩展到发送消息、创建接待员、开票、下单、售后撤销、调价或增加广告预算。动作需要用户选择时，先准备具体对象、字段差异、内容与预计数量，再询问尚缺的决定。

保留工具声明的业务前置条件：商品变更的 `before_check` 成功后才能对应 `execute`；创建接待员先模拟确认，`create_cow_boy` 非幂等，未知结果时不能重复创建；知识入库须满足工具说明的问题和答案确认要求。未知结果的写入先回读再判断，禁止自动重试导致重复发送、重复创建或重复订单。

原始插件需要 Accio 特定卡片时，在当前宿主用普通表格/文本呈现同样的业务对象与选择；不能伪造按钮完成状态。缺少原始 workflow 引擎时使用可见工具实现明确的步骤，缺工具的步骤记为未完成。不得凭脚本文件存在就直接执行其远端调用、安装依赖或启动服务。

所有实际修改使用[共用执行协议](execution-protocol.md)保存结构化变更单、既有行动检查、前置校验、回执及回读。它是文档约定，不是已经实现的写入代理、程序锁或网关拦截。模型和工具访问可能由宿主继承给子 Agent；角色名称不隔离权限。投放策略分析与广告写入能力分开：未核实可用的广告写接口、参数、权限和回读时，只交付策略与未接通项，不能声称已调整预算或创建计划。

## 商品编辑字段边界

按2026-10-27用户提供的商品编辑截图及明确要求，已有商品修改须先区分“基础信息”与“销售信息”。当前接入工具没有与“销售信息”区域对应的编辑接口；用户要求修改该区域字段时，必须明确说明具体哪些字段需要用户在1688商品编辑页手动修改，不能承诺自动完成。

标题、主图的候选写入能力不证明详情也有写入接口。详情同样先完成最终文稿、所需图片与检查；用户审核通过后，按实时工具说明核实详情字段、资源格式及回读能力。确实不可用时交付该获批版本的具体人工编辑材料、位置和回执要求，不猜接口、不以其他字段代写。

- **基础信息中的尺寸**：可以作为基础属性编辑，但须核对当前类目支持的属性名称和值，并遵守属性修改的前置校验。执行和交付均写明“基础信息—尺寸”；这不改变销售SKU的尺寸、规格组合或对应价格库存。
- **销售信息中的字段**：包括产品规格的颜色、颜色图片、SKU尺寸及规格组合，网上订购、计量单位、报价方式、区间报价的购买数量和单价，以及SKU可售数量、单品货号、69码/UPC、SKU“是否上架”、库存扣减设置、属性定制及定制项等。该区域的其他待编辑字段同样按手动编辑处理；“累计订购数量”等统计展示值不承诺可以手动修改。
- **相似名称不能混用**：基础属性接口不等于销售规格接口；商品主图不等于SKU颜色图片；整件商品上/下架不等于SKU行的上架开关。目录中“一键操作”提到库存、打折，也不能据此推定能编辑上述销售信息字段，不用通用属性或一键接口试写该区域。
- **混合请求分别交付**：继续完成已授权且接口支持的基础信息等修改，并逐项列出销售信息的待手动编辑字段及用户要求的目标值。用户明确要求修改SKU尺寸时，应说明需手动编辑，不能擅自用基础信息尺寸代替；基础信息尺寸也在授权范围内时可单独完成并注明落点。
- **提醒与结果表述**：例如“尺寸可写入基础信息；颜色、SKU尺寸/库存及阶梯价格属于销售信息，当前没有对应编辑接口，需要您在1688后台手动编辑。”按实际请求列举字段，仅记录实际完成的修改，未操作的销售信息标记“待用户手动编辑”。后台回读不证明买家页面展示正常，实际展示效果核查仍遵守项目的独立授权规则。

## 数据和交接

涉及 `/item/skuStockWarning` 时，先按[库存预警字段与校验](stock-warning-contract.md)运行本地归一化，再传递或汇总结论。原接口的预警等级、库存缺口、预警总数均为离线候选口径，不能直接当成当前缺货、当前补货量或当前风险数。所有角色共用同一规则；不要改原始回执或店铺库存来消除旧预警。

日期按用户时区解释，本项目默认 Asia/Shanghai。日报 T+1，仅单日，默认昨日；长周期用支持对应周期的查询工具。不同工具周期枚举不互相套用。记录店铺归属、时间区间、币种、分页、数据源；缺失值不是零，环比和 ROI 给出分母与口径。

保留 `storeAttribution`；把事实、计算、推断、建议区分开。商品 ID 对外展示为 `[数字ID](https://detail.1688.com/offer/数字ID.html)`。不要导出或复制凭证、token、cookie；使用现有网关授权。CRM 的 `LOGINID_..._LOGINID` 保持原样；原插件声明的客户明细导出限制仍适用，可给聚合分析和不超过20条示例，不能用分页拼接绕过。

跨 Agent 交接只传任务相关事实：用户目标、授权范围、真实店铺引用、对象 ID、时间范围、已检索数据/工具、建议动作、既有行动及观察状态、未解决项。可并行只读查询；依赖前一结果或会改变同一对象的步骤顺序执行。使用真实子代理ID记录启动与返回，不把读取技能说成启动专员。

周期任务从[账本查询](operating-state.md)取得当前策略引用、既有行动、到期事项和数据截止；首次核对历史后再建档。三类基线及观察判断按[运营周期](operating-cycle.md)相关章节；转化问题仅存于[转化状态模块](conversion-state.md)。摘要不是第二份状态，也不证明业务已执行。定时任务尚未开启，本地文件操作不提供远端业务锁。

交付应包含结论、关键依据、具体已完成动作和回执、未完成或受限部分。工具目录可见不代表业务执行成功；尚未实际调用时只说明准备就绪。
