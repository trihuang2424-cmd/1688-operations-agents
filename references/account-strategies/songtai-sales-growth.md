# 浙江淞泰科技｜当前阶段运营策略

策略ID：songtai-sales-growth；版本：3；生效日期：2026-11-08（Asia/Shanghai）。适用于本项目的浙江淞泰科技1688账号，直至用户调整。沿用销售增长、固定价格、完整周期比较与长期重点跟踪。2026-11-08 用户明确：账号分析按曝光、点击率、新客询盘、询盘成交逐层诊断；投放重视新客效果并核实成交身份；整体成交额保留，新客成交额可作为拆分项但必须明确展示；有依据的商品优化先交真实成品审核，通过后直接接口应用。修改前版本保存在 Git 标签 `baseline-20261108-before-acquisition`。

这是本店当前目标与调度依据，优先于历史档案及通用场景中的默认利润前置、调价建议；不改写原始经营数据，不将这一策略套用到其他店铺。调用业务工具时仍使用网关确认的真实店铺引用，本地策略名不是store_ref。

## 目标与固定条件

- 主要经营结果保留整体成交额及其变化，分别追踪新品和重点商品贡献；明确展示公司新客、老客、身份未知的成交拆分及覆盖，不用新客或单条链接增长替代全店结果。公司身份与平台身份、广告来源分别核实，见[获客分析口径](../acquisition-analysis.md)。
- 账号诊断优先检查全店及核心商品曝光，再看点击量/点击率、到新客有效询盘、成熟询盘到首单转化。投放商品重点评价新客获取和成交，老客订单不计广告拉新；总成交额和平台归因原额继续保留作经营与对账依据。
- 当前暂不做利润优化，不默认调用成本/利润模块，不催补成本表、利润底线或盈亏平衡获客成本，也不因这些资料缺失阻塞新品推广、链接优化和流量测试。历史成本缺口保留，待用户重新提出利润任务时再处理；本阶段不据此输出盈利结论。
- 产品价格按公司已确认的现行规则固定。不得以优化转化为由主动改标价、阶梯价、报价规则，或通过折扣、优惠券等改变实际成交价格。新品使用公司已确定的价格；价格尚未提供时可以先做资料、素材和推广方案，正式发布/报价涉及的缺项须补齐。
- 客户嫌贵时，核对采购人群、需求匹配、规格/单位/数量说明、产品价值及既有报价是否准确；如实记录价格异议，不自动进入降价或利润测算分支。历史老客特殊价格的记载不构成Agent改价授权，由公司按已确认条件处理。
- 推广预算及实际消耗仍须记录，具体投入沿用已有授权范围，不把销售额目标或历史充值余额解释为本轮可任意花费的授权。消耗、获询成本和广告产出比可辅助比较渠道效率，不作为利润门槛。
- 真实商品信息、供货、交期、接待能力与既有人工审核继续有效。标题、主图、详情的审核依账号档案F08及已有具体授权执行。

## 三条重点工作与调用

以上工作统一按[销售增长运营流程](../sales-growth-workflow.md)推进：完整周/月与可比基线先形成流量至新客成交的瓶颈判断，同时明确整体成交额与新老客拆分，再排序逐链接动作。公司指定重点产品可直接立项，长期身份与单次措施观察分别维护；投流先形成方案，按已有授权和可用能力执行，每日检查。具体比较周期、行动记录和验收以该流程为准，未指定重点产品/预算时不补造清单或数字。

| 工作线 | 调用与交付 | 主要判断 |
|---|---|---|
| 新品推广 | 总控确定本轮商品范围与目标；商品运营核实定位、采购客群、价格及供货事实，准备标题/图片/属性/详情表达；流量运营制定自然流量与适用付费渠道的测试方案；具备能力和授权的步骤执行，其余列明人工事项 | 新品是否获得相关流量、有效询盘/直接订单、样单到大货推进及销售额；不能因没有历史数据直接判失败，也不等成本资料齐全才出方案 |
| 商品链接流量 | 流量运营先拆搜索、推荐、广告等来源及有依据的搜索词/点击表现；需要商品表达改进时由总控交商品运营处理 | 是曝光不足、点击不足还是来客不匹配；按证据决定改词、改表达或调整推广建议，不把所有低流量都归因主图 |
| 商品链接转化 | 商品运营检查采购信息、规格和价值表达；出现询盘质量、接待、报价信息或跟进疑问时，总控按现有触发条件委派conversion_analysis | 分开看访问到询盘、访问到直接成交、成熟询盘到订单，以及样单到大货；优先解决信息和承接问题，价格保持固定 |

总控按核心商品覆盖、获客瓶颈、销售影响、证据、时效、实施依赖及既有观察状态排序，同一问题复用已有措施。新品推广与老链接优化可以并行，但同一对象变更须协调；具体重点商品与测试额度由实际任务及已有授权确定，未指定时先做可完成的梳理与方案，不编造优先SKU或预算数字。

## 商品成品与审核范围

用户已确认本店正常经营和投放优化任务：有证据支持标题、主图或详情表达改动时，继续完成可审核的实际文案/图片，说明对应商品、字段、版本与简短理由；用户批准该具体版本后，按实时核实的接口能力完成必要上传、商品应用、回读及效果观察。该范围由总控传入任务包，是成品制作和审核后应用的依据，未审核不得写商品；同一版本不再追加例行执行批准。明确仅查证、仅方案、不生成或不应用的当前指令优先。纯取数、规则讨论或本地代码修改不因此触发真实业务。

流程和记录方式统一见[成品审核与应用](../sales-growth-workflow.md#成品审核与应用)。本范围针对已有商品的标题、主图、详情表达；不新增广告预算、价格、客户触达或新商品发布授权，也不改变既定生图后端及实际页面核查约定。

## 评价口径

整体经营结果保留同口径的平台支付成交金额，注明店铺/商品、期间及截止，并展示公司新客、老客、身份未知拆分；平台新客标签另列，不替代公司历史核验。站外成交仅在有匹配证据时单列并去重，不混入平台口径。支付订单/买家、销售件数作为解释项；退款与取消另列。老客成交仍是经营收入，不能据此证明广告拉新；归因报表的新客成交也需独立核实获客来源。

过程观察相关曝光、点击或访客、有效询盘、报价/寄样、样单与首笔大货推进。指标链不完整不强算转化率；直接下单和询盘成交分别观察，样单不冒充大货，过程提升不写成已实现销售增长。新品零基线使用绝对金额、订单及阶段推进，不计算从零增长百分比。

比较销售额时保留固定基线、同期活动与大单等影响；按采购周期、样本和回补条件判断成效。已证实的报价、寄样等过程超时仍及时调查，不等待成交成熟。

## 通用场景在本店的适配

| 原场景 | 当前阶段处理 |
|---|---|
| J07、J10：价格/规格/MOQ等影响点击或询盘 | 核查展示、单位与真实条件，调整适用表达或采购人群；价格差距可报告，不默认测利润或调价，MOQ/交期也不擅改 |
| J15：报价逻辑、价格异议 | 核对是否正确使用现行价格和费用规则；事实错误先形成具体纠正方案，执行依授权，不因嫌贵更改价格规则 |
| J18：有效商品做法复制 | 看销售与有效询盘证据，选择适用商品小范围复制；成本/利润资料不是前置条件 |
| J20：利润下降或履约压力 | 利润部分当前不主动开展；供货、接待、履约对成交的影响继续处理 |
| J21：新品机会 | 已确定新品按现行价格和真实供货条件推进资料、发布准备与推广，不强制先做利润核算；草稿不等于正式上线 |

本策略确定经营方向、调度优先级和上述商品成品准备/审核后应用范围，不代表具体成品已获批准或业务已执行。执行入口沿用[运营周期](../operating-cycle.md)、[场景调用](../operating-scenarios.md)和[任务路由](../../catalog/task-routing.json)。
