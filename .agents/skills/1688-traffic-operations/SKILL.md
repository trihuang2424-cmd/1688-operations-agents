# 1688 流量与投放运营

路由：`traffic_and_ads`。按[阶段加载约定](../../../references/context-loading.md)在项目根运行 `python3 scripts/task_context.py --route <ID> --phase <阶段> --role executor`（仅协调用 `director`；条件用 `--condition`），读取本阶段依赖。实际分析、制定业务方案或执行前须完整读取适用 `RULES.md` 及必需来源，摘要不能替代；纯本地恢复、状态检查或回执只读本阶段清单。去重、父子上下文和旧名处理遵循统一约定。

`traffic_operations` 直接处理具体流量任务，不再启动本角色或总控。输入为真实店铺引用、周期、目标、商品状态、策略版本、已有措施及授权；恢复相关[对象状态](../../../references/operating-state.md)。开展渠道分析、投流方案或业务执行时完整读取[原流量分析规则](../../../references/business-rules/1688-traffic-analyst/RULES.md)及必需来源。

| 本轮阶段 | 读取与任务重点 |
|---|---|
| 计划 | [重点推广与每日投流](../../../references/sales-growth-workflow.md#重点推广与每日投流)：具体链接、目标、渠道/人群、预算上限、周期、素材承接、指标成熟度及干预/停止条件 |
| 执行 | [执行协议](../../../references/execution-protocol.md)：依已有授权、合同和已验证实时能力提交或交完整人工方案，保留回执与回读 |
| 监测 | 同一投流章节的日检要求：最近完整日及累计结果，调整须有新证据或已达干预条件，留策略版本；不自动创建定时任务 |
| 评估/生效回执 | [两类观察](../../../references/sales-growth-workflow.md#两类观察)：长期 `focus_id` 和有限 `action_id` 分开，实际生效后才观察 |

周/月复盘任务复用总控的完整周期数据和[经营结论](../../../references/sales-growth-workflow.md#经营结论)，缺口按[完整周期与比较基线](../../../references/sales-growth-workflow.md#完整周期与比较基线)补齐。沿曝光、点击/访客、直接下单及有效询盘到成熟成交定位证据支持的环节，同时核对采购量、商品结构和大单节奏；不能把相关变化写成因果。明确的小任务保持指定范围。

广告分析、建议和复核必须读[广告经营决策修正规则](../../../references/ad-decision-policy.md)，限定修正优先于来源中的相反条款，其他来源规则继续有效。浙江淞泰科技保持价格固定、投入不超授权，不以成本/利润资料阻塞本次方案。

查询能力不代表广告写入能力。缺少已验证写接口、参数、权限或回读时，交付完整人工方案及待执行/待回执项，不能称已投放。每天观察不要求每天修改，措施完成不取消重点身份。返回证据、计划及策略版本、真实执行状态、依赖和评估条件；商品修改交总控协调，同一对象不由多个任务各自修改。
